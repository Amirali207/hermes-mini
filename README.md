# hermes-mini

### دستیار کارهای روزانه در تلگرام، بدون هیچ سروری

</div>

<div dir="rtl">

`hermes-mini` یک ربات تلگرام است که کارهای روزانه‌تان را یادداشت می‌کند. فرقش با ربات‌های معمولی این است که لازم نیست دستوری حفظ کنید. مثل چت با یک آدم می‌نویسید «شیر بخر» یا «شیر رو خریدم» و ربات خودش می‌فهمد منظورتان چیست.

این پروژه برای درس **محاسبات ابری** ساخته شده و کاملاً روی **پلن رایگان Cloudflare** اجرا می‌شود. یعنی نه سروری می‌خرید، نه چیزی را شبانه‌روز روشن نگه می‌دارید.

## در یک نگاه

**ربات چه کاری می‌کند؟**
کارهای روزانه را اضافه می‌کند، تیک می‌زند، حذف می‌کند، فهرست می‌کند و در آن‌ها جستجو می‌کند. اگر برای کاری ساعت بگویید، سر ساعت یادآوری می‌فرستد. هر روز صبح هم فهرست امروز را برایتان می‌فرستد.

**چه کسی می‌تواند ازش استفاده کند؟**
فقط یک نفر: صاحب ربات. ربات به پیام بقیه جواب نمی‌دهد.

**زبان ربات؟**
فارسی. پیام‌ها را به فارسی و آزاد می‌نویسید، مثلاً «جلسه ساعت ۵ عصر» یا «نان رو خریدم».

**هوش مصنوعی کجای کار است؟**
هر پیامی که می‌فرستید به یک مدل زبانی داده می‌شود. مدل فقط تشخیص می‌دهد شما چه می‌خواهید (اضافه کردن؟ حذف؟ فهرست؟) و جوابش را به شکل یک خط JSON می‌دهد. بعد برنامه خودش همه‌چیز را چک می‌کند و کار را انجام می‌دهد. مدل مستقیم به دیتابیس دسترسی ندارد.

**چه چیزهایی می‌فهمد؟**

| شما می‌نویسید | ربات چه می‌کند |
|---|---|
| `خرید نان` | کار را اضافه می‌کند و ساعتش را می‌پرسد |
| `جلسه ساعت ۵ عصر` | کار را با ساعت ۱۷:۰۰ اضافه می‌کند |
| `نان رو خریدم` | کار را تیک می‌زند |
| `زنگ مامان هنوز مونده` | تیک کار را برمی‌دارد |
| `چیه کارام` | فهرست کارهای امروز را نشان می‌دهد |
| `شماره ۲ رو حذف کن` | کار شمارهٔ ۲ را حذف می‌کند |
| `همه رو حذف کن` | اول می‌پرسد مطمئنید یا نه |
| `ساعت کار ۲ رو بذار ۸ شب` | ساعت کار را تعیین یا عوض می‌کند |
| `دنبال کار دکتر بگرد` | در همهٔ روزها جستجو می‌کند |
| `سلام` | جواب می‌دهد و گپ می‌زند (با یک حافظهٔ کوتاه) |

## یک گفتگوی نمونه

این یک گفتگوی واقعی با ربات است:

| | پیام |
|---|---|
| شما | `خرید نان` |
| ربات | ✚ اضافه شد: خرید نان. ساعتش چنده؟ |
| شما | `بی‌ساعت` |
| ربات | 👌 بدون ساعت: خرید نان |
| شما | `همه رو حذف کن` |
| ربات | ⚠️ ۱ کار حذف بشه؟ «خرید نان». بنویس «بله» تا حذف بشه، یا «نه» برای لغو. |
| شما | `نه` |
| ربات | باشه، چیزی حذف نشد 👌 |
| شما | `نان رو خریدم` |
| ربات | ✅ تیک خورد: خرید نان |

دقت کنید ربات قبل از هر حذف دسته‌جمعی تأیید می‌گیرد. دلیلش را در بخش «ایمنی» می‌خوانید.

## اصطلاحاتی که در این متن می‌بینید

اگر با دنیای Cloudflare آشنا نیستید، این جدول کمکتان می‌کند:

| اصطلاح | یعنی چه |
|---|---|
| **Worker** | برنامهٔ کوچکی که روی سرورهای Cloudflare اجرا می‌شود، آن هم فقط وقتی درخواستی برسد. کد ربات همین است. |
| **Serverless** | سرور نمی‌خرید و مدیریت نمی‌کنید. پلتفرم هر بار که لازم شود برنامه را اجرا می‌کند. |
| **D1** | دیتابیس SQL خود Cloudflare. کارها و حافظهٔ ربات اینجا ذخیره می‌شود. |
| **Webhook** | آدرسی که تلگرام هر وقت پیام تازه‌ای رسید، به آن خبر می‌دهد. برنامه مدام از تلگرام نمی‌پرسد. |
| **Secret** | رمزی (مثل توکن ربات) که فقط در گاوصندوق Cloudflare ذخیره می‌شود و در فایل‌های پروژه نیست. |
| **Migration** | یک فایل SQL شماره‌دار که جدول‌های دیتابیس را می‌سازد یا تغییر می‌دهد. |
| **مدل زبانی (LLM)** | هوش مصنوعی‌ای که متن را می‌فهمد. |
| **Workers AI** | سرویس Cloudflare برای اجرای مدل‌های زبانی. کلید API جدا نمی‌خواهد. |
| **Cron Trigger** | زمان‌بندی خودکار. Worker را در زمان‌های مشخص اجرا می‌کند (برای یادآوری‌ها). |
| **Neuron** | واحدی که Cloudflare مصرف هوش مصنوعی را با آن می‌شمارد. سهمیهٔ رایگان روزانه دارد. |
| **Wrangler** | ابزار خط فرمان Cloudflare برای deploy و مدیریت Worker و دیتابیس. |

## ربات چطور کار می‌کند

نقشهٔ کلی:

```
 You (Telegram app)
        |
        v
 Telegram Bot API --- webhook POST (secret header) --->  Cloudflare Worker
                                                              |
                                  +---------------------------+---------------------------+
                                  |                           |                           |
                                  v                           v                           v
                            Workers AI                  D1 (SQLite)              Telegram sendMessage
                     (text -> one JSON action)    tasks, state, messages             (the reply)

 Cron Trigger (every minute) --> Worker --> morning summary + task reminders
```

### مسیر یک پیام، قدم به قدم

1. شما پیامی می‌فرستید. تلگرام آن را با یک درخواست `POST` به آدرس `/webhook` ربات می‌رساند و یک هدر مخفی هم کنارش می‌گذارد.
2. Worker اول هدر را چک می‌کند. اگر درست نباشد، جواب **403** می‌دهد و کار تمام است.
3. Worker شناسهٔ پیام را ثبت می‌کند. اگر تلگرام همان پیام را دوباره فرستاده باشد، نادیده گرفته می‌شود.
4. اگر فرستنده صاحب ربات نباشد، بی‌صدا نادیده گرفته می‌شود.
5. اگر ربات منتظر جواب سؤالی بود (ساعت کار؟ مطمئنید حذف شود؟ این کار تکراری است، اضافه شود؟)، اول جواب شما همان‌جا بررسی می‌شود.
6. در غیر این صورت، پیام شما به همراه فهرست شماره‌دار کارهای امروز و چند پیام آخر گفتگو به مدل داده می‌شود.
7. مدل یک خط JSON برمی‌گرداند. برنامه آن را اعتبارسنجی می‌کند و اگر درست بود، کار را در D1 انجام می‌دهد.
8. ربات جواب را برایتان می‌فرستد.

در همهٔ حالت‌ها (حتی وقتی خطا پیش بیاید) Worker به تلگرام جواب **200** می‌دهد. اگر این کار را نکند، تلگرام فکر می‌کند پیام نرسیده و دوباره می‌فرستد.

### اکشن‌هایی که مدل می‌تواند انتخاب کند

مدل فقط یکی از این‌ها را برمی‌گرداند. اگر خروجی‌اش چیز دیگری باشد، رد می‌شود.

| اکشن | معنی |
|---|---|
| `add` | یک یا چند کار جدید (هر کدام با ساعت اختیاری) |
| `done` | تیک زدن یک یا چند کار |
| `undone` | برداشتن تیک |
| `settime` | تعیین یا تغییر ساعت کار |
| `del` | حذف یک یا چند کار |
| `delall` | حذف همهٔ کارهای امروز (همیشه با تأیید) |
| `list` | نمایش فهرست امروز |
| `search` | جستجو در همهٔ روزها |
| `chat` | گفتگوی عادی |

### یادآوری‌ها (قابلیت امتیازی)

یک Cron Trigger هر دقیقه Worker را صدا می‌زند. Worker دو کار می‌کند:

- اگر ساعت تهران به ساعت تنظیم‌شده (`REMINDER_HOUR`) رسیده باشد و امروز هنوز پیام صبحگاهی نرفته باشد، فهرست امروز را می‌فرستد.
- برای هر کار ساعت‌دار که وقتش رسیده و تیک نخورده، یک بار یادآوری می‌فرستد.

## چرا این‌طور طراحی شده

این‌ها تصمیم‌های اصلی طراحی و دلیلشان است:

**چرا Webhook و نه Polling؟**
در polling باید برنامه‌ای همیشه روشن باشد و هر چند ثانیه از تلگرام بپرسد «پیام تازه‌ای هست؟». در webhook تلگرام خودش وقتی پیامی رسید خبر می‌دهد. برای ربات شخصی که روزی چند پیام می‌گیرد، این خیلی مناسب‌تر است.

**چرا FaaS (همین Workers)؟**
بار کاری این پروژه کوچک و پراکنده است: چند پیام در روز که هرکدام چند میلی‌ثانیه طول می‌کشند. یک سرور یا کانتینر تقریباً تمام روز بیکار می‌ماند و باز هم باید نگهداری می‌شد. با Workers هم HTTPS و TLS آماده است، هم نگهداری secret.

**چرا D1 (دیتابیس رابطه‌ای) و نه KV؟**
ربات مدام سؤال‌هایی می‌پرسد مثل «کارهای امروز»، «مرتب بر اساس ساعت»، «کارهایی که این کلمه را دارند»، «حذف این چند id». در D1 هرکدام یک دستور SQL است. در KV (که فقط کلید و مقدار نگه می‌دارد) باید فهرست و ایندکس را دستی بسازید و بارها بخوانید.

**state کجا ذخیره می‌شود؟**
فقط در D1. Worker بین دو درخواست هیچ چیزی در حافظه نگه نمی‌دارد، پس هرچه باید بماند در یکی از سه جدول است: کارها، حالت‌های موقت (مثل «منتظر جواب ساعت هستم») و تاریخچهٔ گفتگو.

**چرا مدل فقط «پیشنهاد» می‌دهد؟**
مدل‌های زبانی گاهی اشتباه می‌کنند. برای همین مدل هیچ‌وقت مستقیم به دیتابیس دست نمی‌زند. فقط یک اکشن پیشنهاد می‌دهد و کد خود برنامه آن را چک می‌کند و تصمیم می‌گیرد اجرا شود یا نه. با خروجی مدل مثل ورودی یک غریبه رفتار می‌کنیم.

### «امروز» یعنی چه؟

«امروز» یعنی تاریخ **به وقت تهران** (`Asia/Tehran`، یعنی UTC+3:30 و بدون ساعت تابستانی). Worker روی سرورهای Cloudflare و در UTC اجرا می‌شود و منطقهٔ زمانی خودش را ندارد. برای همین در هر درخواست، تاریخ و ساعت را با `Intl.DateTimeFormat` و `timeZone: 'Asia/Tehran'` حساب می‌کنیم. زمان‌بندی cron هم در UTC است؛ به همین دلیل cron هر دقیقه اجرا می‌شود و خود کد چک می‌کند ساعت تهران چند است.

## ایمنی و پایداری

مهم‌ترین قاعده: **اگر چیزی مشکوک بود، هیچ‌چیز نوشته یا حذف نمی‌شود.**

- **فقط صاحب ربات.** هر پیام از کسی غیر از کاربر مجاز بی‌صدا نادیده گرفته می‌شود.
- **درخواست بدون هدر درست، 403 می‌گیرد.** یعنی کسی نمی‌تواند خودش را جای تلگرام جا بزند.
- **خروجی مدل چک می‌شود.** JSON پارس می‌شود، نوع هر فیلد بررسی می‌شود و شمارهٔ کارها با فهرست واقعی مقایسه می‌شود. اگر چیزی درست نباشد، ربات می‌گوید «متوجه نشدم» و چیزی نمی‌نویسد.
- **حذف باید «مستند به پیام» باشد.** اگر بنویسید «شماره ۲ رو حذف کن»، همان لحظه حذف می‌شود چون کار را مشخص کرده‌اید. اگر بنویسید «حذفش کن»، ربات حدس نمی‌زند و تأیید می‌گیرد. حذف چند کار و «حذف همه» همیشه تأیید می‌خواهند و تأیید بعد از ۵ دقیقه منقضی می‌شود.
- **کار تکراری.** اگر کاری با همان متن و همان ساعتِ یک کار باز امروز بفرستید، ربات می‌پرسد «باز هم اضافه شود؟». ساعت متفاوت یعنی کار متفاوت (مثلاً «خرید نان ساعت ۸» و «خرید نان ساعت ۱۲»).
- **پیام تکراری تلگرام.** هر پیام یک شناسهٔ یکتا (`update_id`) دارد. اگر تلگرام یک پیام را دو بار بفرستد، بار دوم نادیده گرفته می‌شود.
- **جواب ساعت سخت‌گیرانه چک می‌شود.** وقتی ربات می‌پرسد «ساعتش چنده؟»، فقط جوابی که شامل کلمه‌های ساعت باشد قبول می‌شود. اگر به‌جای ساعت، کار جدیدی بنویسید، آن را کار جدید حساب می‌کند.
- **هیچ رمزی در مخزن نیست.** توکن‌ها فقط در گاوصندوق Cloudflare هستند، نه در کد و نه در تاریخچهٔ git.

## داده‌ها کجا ذخیره می‌شوند

دیتابیس D1 سه جدول دارد. ساختار آن‌ها در پوشهٔ `migrations/` است، جدا از کد برنامه.

| جدول | برای چیست |
|---|---|
| `tasks` | خود کارها: متن، تیک‌خورده یا نه، روز، ساعت و اینکه یادآوری رفته یا نه |
| `state` | حالت‌های موقت (کلید و مقدار): منتظر جواب ساعت، منتظر تأیید حذف، شناسهٔ پیام‌های دیده‌شده و نشانهٔ پیام صبحگاهی |
| `messages` | چند پیام آخر گفتگو، برای حافظهٔ کوتاه حالت `chat` |

| فایل migration | چه چیزی می‌سازد |
|---|---|
| `0001_init.sql` | جدول `tasks` و یک ایندکس روی روز |
| `0002_*.sql` | ستون‌های `time` و `reminded` و جدول `state` |
| `0003_add_messages.sql` | جدول `messages` |

قاعدهٔ مهم: migration ی که یک بار اعمال شده را **هرگز ویرایش نکنید**. برای هر تغییر، یک فایل شماره‌دار تازه اضافه کنید.

## تنظیمات

**تنظیمات عمومی** در فایل `wrangler.jsonc` هستند و اشکالی ندارد در git باشند:

| تنظیم | معنی |
|---|---|
| `d1_databases` | اتصال به دیتابیس: نام اتصال `DB`، نام دیتابیس و شناسهٔ آن |
| `ai` | اتصال به Workers AI با نام `AI` |
| `vars.AI_MODEL` | نام مدلی که پیام‌ها را می‌فهمد |
| `vars.ALLOWED_TELEGRAM_ID` | شناسهٔ عددی تنها کاربر مجاز |
| `vars.REMINDER_HOUR` | ساعت (به وقت تهران) پیام صبحگاهی |
| `triggers.crons` | زمان‌بندی cron (هر دقیقه) |
| `observability` | روشن بودن لاگ‌ها |

**رمزها (Secret)** هرگز در فایل نمی‌آیند و با Wrangler ذخیره می‌شوند:

| Secret | چیست |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توکنی که @BotFather به شما می‌دهد |
| `TELEGRAM_WEBHOOK_SECRET` | یک رشتهٔ تصادفی بلند که خودتان می‌سازید. تلگرام آن را در هدر هر درخواست برمی‌گرداند |

## راه‌اندازی قدم‌به‌قدم

### پیش‌نیازها

- **Node.js** (نسخهٔ LTS) از سایت nodejs.org
- **Git**
- یک **حساب Cloudflare** (رایگان) که زیر‌دامنهٔ `workers.dev` در آن ثبت شده باشد. این را در داشبورد، بخش Workers & Pages، می‌توانید بسازید. اگر ثبتش نکنید، هنگام deploy خطای `10405` می‌گیرید.
- یک **ربات تلگرام**: در تلگرام به @BotFather پیام بدهید، دستور `/newbot` را بزنید و توکن را نگه دارید.
- **شناسهٔ عددی تلگرام خودتان**: از یک ربات مثل @userinfobot می‌توانید بگیرید.
- اگر در ایران هستید: ترمینال هم باید از **VPN** رد شود، نه فقط مرورگر.

### ۱. گرفتن کد و نصب وابستگی‌ها

</div>

<div dir="ltr">

```bash
git clone https://github.com/Amirali207/hermes-mini.git
cd hermes-mini
npm install
npx wrangler login
```

</div>

<div dir="rtl">

دستور آخر مرورگر را باز می‌کند تا به Wrangler اجازه بدهید به حساب Cloudflare شما وصل شود.

### ۲. ساختن دیتابیس و جدول‌ها

</div>

<div dir="ltr">

```bash
npx wrangler d1 create hermes-mini
```

</div>

<div dir="rtl">

خروجی یک `database_id` به شما می‌دهد. آن را در `wrangler.jsonc` بگذارید، طوری که فقط **یک** ورودی در `d1_databases` باشد، با `binding` برابر `DB` و `database_name` برابر `hermes-mini`. بعد جدول‌ها را بسازید:

</div>

<div dir="ltr">

```bash
npx wrangler d1 migrations apply hermes-mini --remote
```

</div>

<div dir="rtl">

کلمهٔ `--remote` یعنی «روی دیتابیس واقعی». بدون آن، فقط یک نسخهٔ محلی روی کامپیوتر خودتان تغییر می‌کند و Worker واقعی جدولی نمی‌بیند.

### ۳. ذخیرهٔ رمزها

</div>

<div dir="ltr">

```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_WEBHOOK_SECRET
```

</div>

<div dir="rtl">

هر دستور مقدار را از شما می‌پرسد (چیزی که تایپ می‌کنید نمایش داده نمی‌شود). برای دومی یک رشتهٔ تصادفی بلند بسازید (مثلاً با `openssl rand -hex 32`) و **آن را جایی امن نگه دارید**، چون در مرحلهٔ ۵ دوباره لازمش دارید و بعداً نمی‌شود آن را از Cloudflare خواند.

### ۴. تنظیم و deploy

در `wrangler.jsonc` مقدار `ALLOWED_TELEGRAM_ID` را به شناسهٔ خودتان تغییر دهید و `AI_MODEL` را روی یک مدل موجود بگذارید (فهرستشان را با `npx wrangler ai models list` ببینید). بعد:

</div>

<div dir="ltr">

```bash
npx wrangler deploy
```

</div>

<div dir="rtl">

در پایان، آدرس Worker چاپ می‌شود، چیزی شبیه `https://hermes-mini.<subdomain>.workers.dev`. آن را یادداشت کنید.

### ۵. وصل کردن تلگرام به Worker

به تلگرام بگویید پیام‌های ربات را به کجا بفرستد. `secret_token` باید **دقیقاً همان** رشته‌ای باشد که در مرحلهٔ ۳ ذخیره کردید:

</div>

<div dir="ltr">

```bash
curl "https://api.telegram.org/bot<BOT_TOKEN>/setWebhook" \
  -d "url=https://<worker>.<subdomain>.workers.dev/webhook" \
  -d "secret_token=<WEBHOOK_SECRET>"
```

</div>

<div dir="rtl">

اگر جواب `{"ok":true,...}` بود، آماده‌اید. در PowerShell ویندوز به‌جای `curl` بنویسید `curl.exe`.

### ۶. امتحان

در تلگرام به رباتتان بنویسید «سلام». باید جواب بدهد. بعد بنویسید «خرید نان» تا ببینید کار اضافه می‌شود.

## مطمئن شوید کار می‌کند

این چند دستور نشان می‌دهند همهٔ بخش‌ها سالم‌اند:

</div>

<div dir="ltr">

```bash
# health check: should print "hermes-mini is up" (HTTP 200)
curl -i https://<worker>.<subdomain>.workers.dev/

# unsigned request: must be rejected with 403
curl -i -X POST https://<worker>.<subdomain>.workers.dev/webhook -d "{}"

# live logs while you message the bot
npx wrangler tail

# look inside the database
npx wrangler d1 execute hermes-mini --remote --command "SELECT id, text, done, time FROM tasks"

# type-check the code
npm run check
```

## اگر کار نکرد

| نشانه | دلیل محتمل و راه‌حل |
|---|---|
| ربات اصلاً جواب نمی‌دهد و در `wrangler tail` هم چیزی دیده نمی‌شود | درخواست به Worker نمی‌رسد. وضعیت webhook را با `getWebhookInfo` بپرسید و به `last_error_message` نگاه کنید. تنظیمات محافظت دسترسی (Cloudflare Access یا Zero Trust) روی آدرس workers.dev را هم در داشبورد چک کنید. |
| `getWebhookInfo` خطای 403 نشان می‌دهد | `secret_token` در `setWebhook` با secret ذخیره‌شده در Cloudflare یکی نیست. هر دو را از نو بگذارید. |
| ربات برای همهٔ پیام‌ها می‌گوید «نتونستم بفهمم» | در `npx wrangler tail` دنبال `ai failed` بگردید. شایع‌ترین دلیل تمام شدن سهمیهٔ رایگان هوش مصنوعی در آن روز است (سهمیه ساعت ۰۰:۰۰ UTC، یعنی ۰۳:۳۰ تهران، دوباره پر می‌شود). یک مدل کوچک‌تر در `AI_MODEL` بگذارید و دوباره deploy کنید. |
| هنگام deploy خطای `10405` | زیر‌دامنهٔ `workers.dev` هنوز ثبت نشده. در داشبورد ثبتش کنید. |
| آدرس Worker در مرورگر باز نمی‌شود، ولی ربات جواب می‌دهد | عادی است. `workers.dev` در برخی کشورها فیلتر است. با `curl` تست کنید، نه با مرورگر. |
| پیام‌ها دو بار پردازش می‌شوند | Worker باید همیشه 200 برگرداند. مطمئن شوید migration ها اعمال شده‌اند، چون ثبت `update_id` در جدول `state` انجام می‌شود. |
| خطای `no such table` یا `no such column` | migration ها را با `--remote` اعمال نکرده‌اید. `npx wrangler d1 migrations list hermes-mini --remote` را بزنید. |

## هزینه

برای یک کاربر، همه‌چیز روی پلن رایگان می‌ماند. چون محدودیت‌ها گاهی عوض می‌شوند، مقدار فعلی را از صفحهٔ قیمت‌گذاری Cloudflare چک کنید.

- **Workers:** هر پیام یک درخواست است. به آن‌ها اجراهای cron را هم اضافه کنید: چون هر دقیقه اجرا می‌شود، حدود ۱٬۴۴۰ اجرا در روز.
- **D1:** هر پیام چند خواندن و نوشتن دارد. هر اجرای cron هم یک کوئری برای پیدا کردن یادآوری‌های موعدرسیده می‌زند.
- **Workers AI:** سهمیهٔ رایگان روزانه با واحد neuron شمرده می‌شود و بین همهٔ مدل‌ها مشترک است. مدل‌های بزرگ‌تر برای هر پیام چند برابر بیشتر مصرف می‌کنند. انتخاب مدل مهم‌ترین اهرم هزینه است.
- **اگر ۱۰٬۰۰۰ کاربر داشتید:** cron ی که برای هر کاربر کوئری بزند مقیاس‌پذیر نیست و سهمیهٔ هوش مصنوعی هم تمام می‌شود. اعداد اندازه‌گیری‌شده و تحلیل کامل در گزارش پروژه آمده است.

## محدودیت‌ها

- طبق طراحی فقط یک کاربر دارد.
- مدل ممکن است جمله‌ای را اشتباه بفهمد. برای همین کارهای مخرب چک و در صورت ابهام تأیید می‌شوند.
- وقتی Workers AI در دسترس نباشد (مثلاً سهمیه تمام شده)، ربات نمی‌تواند کار اضافه کند و می‌گوید متوجه نشده است. ولی هرگز داده‌ٔ اشتباه نمی‌نویسد.
- اگر پردازش یک پیام بعد از ثبت شناسه‌اش خطا بدهد، همان پیام دوباره تلاش نمی‌شود («حداکثر یک بار»). برای یک ربات کارهای روزانه، گم شدن یک پیام بهتر از دو بار انجام شدن آن است.
